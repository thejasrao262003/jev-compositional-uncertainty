## 3. The deterministic selection rule (reproducible without knowing the outcome)

`select_diverse_three(candidates, n_three_way=2, n_two_way=1)`:

1. Sort all 4 qualifying candidates ascending by composition tuple.
2. Partition into THREE_WAY and TWO_WAY groups (order preserved).
3. Take the first `n_three_way=2` THREE_WAY and first `n_two_way=1`
   TWO_WAY items.

**This rule takes no coverage counts, no pairwise-sufficiency
information, and no Jev output as input** — it is a pure function of the
candidate list and two integer parameters, fixed before the candidates
were even discovered. Anyone can reproduce the selection from steps 1-3
alone, without knowing this document's conclusion.

**Robustness check, run and verified**: the alternative allocation
(`n_three_way=1, n_two_way=2`) was also tested. It **independently
clears the sufficiency threshold on all 3 pairs** (M-X 6/9, M-A 6/9,
X-A 9/9) — meaning the specific 2:1 ratio chosen was not necessary to
reach this result. This is direct evidence against the selection rule
having been reverse-engineered to hit the target: a different reasonable
allocation gets there too.

## 4. Excluded candidate and reason

**`(0,1,2,2,2)`** — excluded. Reason: the rule takes only the first
`n_two_way=1` TWO_WAY candidate by ascending sort; `(0,1,2,2,2)` sorts
after `(0,0,2,2,2)` within the TWO_WAY group and is therefore not
selected. **Not excluded for any coverage-outcome reason** — per the
robustness check (§3), including it instead (via the alternative
allocation) would have produced an equally valid, threshold-clearing set.

## 7. Threshold status — matched precedent, not validated sufficiency

`SUFFICIENCY_THRESHOLD = 6` is set **by precedent** (X-vs-A's original
full 6/6 coverage), applied identically to all three pairs. **This is
explicitly not claimed as a scientifically validated sufficiency
level** — whether 6 separating items is actually *enough* to support a
semantic conclusion remains open, tracked in
`score_semantic_identification_protocol.md`'s decision gate, unchanged
by this document.

## 8. Sentence-count metadata — the confound flagged, not resolved

| | Frozen primary | Supplement v1 |
|---|---|---|
| Sentences per item | 4 | 5 |

**Why n=5, stated plainly**: the n=4/3-level composition space is fully
exhausted — all 15 possible multisets are already accounted for across
the primary/supplementary-tie/control/non-discriminative categories (see
`score_semantic_identification_protocol.md` Workstream 3). No additional
n=4 M-vs-A-separating composition exists to add; n=5 was the smallest
larger space with any qualifying candidates at all.

**The confound, named explicitly (per review)**: composition-level
pairwise separation (the M/X/A *mathematical* relationship) is unaffected
by sentence count and has been verified independently of it (§5). But
**input length itself is a separate, untested variable**: whether Jev's
actual aggregation behavior differs between 4- and 5-sentence inputs is
unknown, and unrelated to which severity levels those sentences carry.
**No n=5 control item exists yet** to isolate this — a real, currently
unresolved gap, not papered over.

**Binding rule for any future results write-up**: keep three things
separate, never blended into one conclusion:
1. Composition-level pairwise separation — verified here, mathematical.
2. Input-length effects — **not tested**, no isolating control exists.
3. Actual Jev semantic evidence — **not yet collected**, no API call made.

## 9. No selection based on Jev outputs

Confirmed structurally: `design_score_mvsa_supplement.py` makes zero API
calls, imports no network/client code, and reads no response data of any
kind. Candidate discovery and selection are pure functions of composition
arithmetic (mode/max/mean) defined and run before any data could exist.

## 10. Decision gate — semantic and research validity remain open

Per `score_semantic_validation_specification.md` §8's three-tier
hierarchy, restated here as this document's own explicit gate: everything
above addresses **coverage/design-level** questions only.

- **Verifier/design validity**: addressed by this document and its
  script — the supplement's fixtures are internally sound, its selection
  rule is reproducible and robustness-checked, and it closes the
  identified numeric coverage gap.
- **Semantic validity** (is M, X, or A actually `score`'s intended
  target?): **unchanged, still fully open.**
- **Research validity** (is 6-per-pair, across 9 items of mixed sentence
  length, actually adequate to support a conclusion?): **unchanged, still
  fully open** — and now has one more named open dimension (the n=4/n=5
  confound, §8) than it did before this document.

**Nothing in this document authorizes building the supplement into real
manifest items, estimating an API budget, or making any call.** That
remains the next, separate, explicitly-not-yet-taken step.
